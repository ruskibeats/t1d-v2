# T1D Companion Mobile — Full Context

## Purpose

This React Native / Expo app is the **mobile companion** to the T1D CLI showcase runner. It renders the same forecast cards that the terminal produces, using designs generated by Google Stitch. The app must be **visually 1:1 with Stitch** — not just data-compatible.

## Architecture

```
Terminal CLI (Python)
  → CompanionRunEnvelope (JSON)
    → Stitch MCP (design)
      → React Native CardRenderer (render)
        → localhost:8081 (QA)
```

### Key constraint

**Never claim 1:1 based on data/schema alone.** Every screen must be visually compared against Stitch HTML/screenshots before saying it matches.

- 8px grid: `xs 4px`, `sm 12px`, `md 16px`, `lg 24px`, `xl 32px`, `2xl 48px`

- Card internal padding: `16px` (`spacing.md`)

- Cards: `24px` border radius (`rounded-2xl`)
- Item rows: `16px` border radius (`rounded-xl`)
- Pills/buttons: `9999px` (full round)
- Icon bubbles: `20px` (40×40 circle)

- Level 1 (cards): `0px 4px 20px rgba(0,0,0,0.05)` — `ambient-shadow-level-1`

## Data Flow

### Generating a forecast

1. User enters meal text in Log Meal tab
2. `getTomEnvelope(text, mealType)` generates a `CompanionRunEnvelope`
3. Envelope stored in TanStack Query cache: `['companion-run', envelope.runId]`
4. Router navigates to `/forecast/[runId]`
5. Forecast screen reads envelope from cache
6. `CardRenderer` renders each card by `kind`

### Envelope structure

```typescript
interface CompanionRunEnvelope {
  schemaVersion: '1.0';
  runId: string;
  draftId?: string;
  phase: 'preflight' | 'final';
  routeRecommendation: 'final_cards' | ...;
  dataMode: 'synthetic_demo' | 'real_user';
  sourceLabel: string;
  parsedFoods?: ParsedFood[];
  cards?: MobileShowcaseCard[];
  safety: SafetyBoundary;
}
```

### Card structure

```typescript
interface MobileShowcaseCard {
  id: string;
  kind: MobileCardKind;
  title: string;
  subtitle?: string;
  summary: string;
  confidenceTier?: 'high' | 'medium' | 'low' | 'unknown';
  source: DataSource;
  safetyFooter: string;
  payload: Record<string, unknown>;
  primaryActions: MobileAction[];
  secondaryActions: MobileAction[];
}
```

## Stitch MCP Integration

### Project

- **ID**: `3768458435933006236`
- **URL**: https://stitch.withgoogle.com/projects/3768458435933006236
- **Auth**: API key in `.mcp.json` → `mcpServers.stitch.headers.X-Goog-Api-Key`

### Key tools

| Tool | Purpose |
|------|---------|
| `list_screens` | List all screens in project |
| `get_screen` | Get HTML + screenshot URLs for a screen |
| `generate_screen_from_text` | Create new screen from prompt |
| `list_projects` | List accessible projects |

### Workflow for new card

1. Add card type to `MobileCardKind` union in `mobileCard.ts`
2. Make showrunner emit that card payload
3. Push to Stitch: `stitch.callTool('generate_screen_from_text', { projectId, prompt, modelId: 'GEMINI_3_1_PRO' })`
4. Pull Stitch HTML: `stitch.callTool('get_screen', { name })`
5. Save HTML to `/tmp/stitch-html/[card-kind].html`
6. Inspect structure, implement RN renderer
7. Use only `StitchNative.tsx` primitives
8. Typecheck + browser QA

## Safety Rules

- No dosing/treatment recommendations in any card
- Every card has `safetyFooter`: "Educational simulation only — not medical advice. No dosing or treatment changes."
- `SafetyBoundary` on every envelope: `{ educationalOnly: true, noDosingAdvice: true }`
- Unsupported card kinds render `UnsupportedCard` (safe fallback)

## Key Lessons

1. **Never claim 1:1 from code alone** — always screenshot compare
2. **Stitch HTML is the spec** — pull it, read the Tailwind classes, map to RN
3. **Shared primitives first** — build `StitchNative.tsx` before screens
4. **Mobile-width canvas** — constrain web preview to ~430px, center it
5. **Cards are 24px radius** — not 16px, not 8px
6. **Shadows are ambient** — `0px 4px 20px rgba(0,0,0,0.05)`, not elevation-heavy
7. **Pills are full-round** — `borderRadius: 9999`, not 8 or 12
8. **Section labels are uppercase** — `textTransform: 'uppercase'`, `letterSpacing: 0.56`
